# Contribuindo com o Bravo Skills

Antes de tudo: **obrigado por ter chegado até aqui.** Este repositório é um projeto vivo, mantido com cuidado, e qualquer contribuição construtiva é bem-vinda.

## Formas de contribuir

### 1. Reportar problemas ou sugerir melhorias

A forma mais simples de contribuir é abrir uma **issue** descrevendo:

- um caso de uso real onde a skill atual não funciona ou não cobre bem;
- um cálculo ou comportamento que parece inconsistente;
- uma sugestão concreta de melhoria.

Quanto mais específico, melhor. Exemplos reais ajudam mais do que sugestões abstratas.

### 2. Discutir antes de implementar

Para mudanças não-triviais (nova funcionalidade, mudança de modelagem, novos outputs), abra primeiro uma **issue** descrevendo a proposta. Conversamos e alinhamos antes de qualquer pull request.

Isso evita esforço desperdiçado e garante que o que entra no repositório está alinhado com o método que sustenta o produto.

### 3. Pull requests

Pull requests são bem-vindos. Pedido único: que a mudança siga o estilo dos arquivos existentes (formatação, linguagem, tom). PRs cirúrgicos — que tocam apenas no que precisam tocar — são revisados mais rapidamente.

### 4. Compartilhar uso real

Se você usou alguma das skills daqui em uma obra ou projeto real, **conte sua experiência**. Pode ser num post no LinkedIn, num comentário, ou direto pelo grupo de WhatsApp da comunidade. Casos reais alimentam a evolução das skills.

## Estilo

- **Linguagem:** português do Brasil em todos os arquivos voltados ao usuário (READMEs, docs, templates). Código pode ter comentários em inglês quando isso facilitar leitura por bibliotecas/comunidade técnica.
- **Tom:** direto, técnico, sem floreio. Imagine o leitor como um engenheiro experiente que tem pouco tempo.
- **Tamanho:** prefira fragmentos pequenos e bem feitos a documentos longos.
